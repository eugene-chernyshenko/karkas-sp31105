# Каркасный дом по СП 31-105-2002 в Blender

Готовый параметрический генератор: спецификация (JSON/dict) → каркас в Blender + проверка
по нормам + ведомость пиломатериалов. **Не пиши генератор заново — используй этот.**

## Быстрый старт

`$KARKAS` ниже — каталог этого скилла. Он может лежать в проекте
(`.claude/skills/karkas-blender`) или глобально (`~/.claude/skills/karkas-blender`) —
скрипты находят себя сами, запускать можно из любого каталога.

```bash
KARKAS=.claude/skills/karkas-blender       # или ~/.claude/skills/karkas-blender

# 1) проверить нормы и получить ведомость, без Blender (быстро, несколько секунд)
python3 $KARKAS/scripts/build_house.py --spec dom_9x7 --out out/dom --check

# 2) построить геометрию, сохранить .blend и отрендерить
/Applications/Blender.app/Contents/MacOS/Blender -b \
    --python $KARKAS/scripts/build_house.py -- \
    --spec dom_9x7 --out out/dom --render --views iso,front,side,top
```

`--spec` принимает путь к своему JSON либо имя готового примера из `$KARKAS/examples/`.
Быстрые правки без файла спецификации:
`--set plan.width=8 --set roof.slope=1:1.71 --set snow_kpa=2.0 --set stud_spacing=400`

Выход: `out/<имя>.blend`, `_report.txt` (проверка + принятые сечения + отметки + ведомость
пиломатериалов и отдельно утеплителя — мешать их объёмы нельзя),
`_bom.csv`, `_members.json`, `_<ракурс>.png`.

**Всегда смотри `_report.txt` и пересказывай пользователю строки `✗` и `!`** — это нарушения
и предупреждения по СП. Генератор строит геометрию даже при ошибках, но молчать о них нельзя.

## Как думать о задаче

1. Уточни **только то, без чего нельзя считать**: габариты в плане, этажность, снеговой район
   (кПа), тип крыши и уклон. Остальное бери из умолчаний и скажи, что принял.
2. Прогоняй сперва `--check` — это секунды. Правь спецификацию, пока `✗` не исчезнут.
3. Только потом строй в Blender и рендери.
4. Отвечай числами из отчёта («балки 38x235 @ 400 мм, пролёт 3,8 м ≤ 3,96 м по табл. Б-1»),
   а не общими словами.

## Живая модель в Blender

Чтобы у пользователя в Blender всегда была актуальная версия, держи модель по одному
пути и пересобирай туда же:

```bash
blender -b --python $KARKAS/scripts/build_house.py -- \
    --spec out/current.json --out out/current --open
```

`--open` запускает Blender, только если этот файл ещё не открыт. Дальше аддон
`karkas_autoreload` (ставится `tools/install_autoreload.sh`) сам перечитывает файл
после каждой пересборки — проверить можно по `~/.cache/karkas/autoreload.log`.
Если в сцене есть несохранённые правки, аддон перезагрузку пропускает.

Не плоди имён вроде `model_v2.blend` для одной и той же модели — у пользователя
останется открытым старый файл.

## Самопроверка

После правок в `scripts/karkas/` прогоняй:
```bash
python3 $KARKAS/scripts/selftest.py
```
Сверяет ~35 контрольных значений прямо из таблиц СП и собирает эталонный дом.

### Выключатели слоёв

Чтобы показать внутренности каркаса, выключай слои через `hidden` в спецификации —
тогда состояние не потеряется при пересборке. Гасятся все три выключателя Blender
(галочка View Layer, иконка монитора, видимость в рендере), камера кадрируется
по оставшимся слоям. Разово, без правки спецификации — флаг `--hide`:

```bash
python3 $KARKAS/scripts/build_house.py --spec out/current.json --out out/current \
    --hide крыша --hide фундамент
```

Утеплитель идёт отдельными слоями (`11_Утеплитель_стен`, `12_Утеплитель_чердака`),
а не внутри стен и крыши: иначе выключатель крыши прятал бы утеплитель чердачного
перекрытия, а сама эта плита 6х6 при выключенной крыше накрывает каркас сверху
и смотреть внутрь нечем.

Вернуть слой — убрать его из `hidden` и пересобрать. Неизвестное имя слоя
генератор не пропускает молча, а пишет `[!]` со списком псевдонимов.

## Что проверяется автоматически

- **4.2.1** — этажность, высота этажа, шаг стоек, доля проёмов ≤30 % площади каждой несущей стены,
  снеговая нагрузка ≤3,0 кПа.
- **Табл. 7-1** — сечение/шаг/свободная высота стоек по виду стены и воспринимаемой нагрузке.
  Сечение крупнее табличного при том же шаге считается соответствующим (таблица задаёт минимум).
- **Табл. Б-1…Б-3** — пролёты балок перекрытий и чердачного перекрытия.
- **Табл. Б-4…Б-7** — пролёты кровельных балок и стропил по снеговой нагрузке.
- **Табл. Б-8…Б-11** — составные прогоны (с интерполяцией по грузовой площади) и коньковые балки.
- **Табл. Б-12…Б-14** — перемычки, с учётом жёсткой обшивки и нагрузки на стену.
- **Табл. 8-1** — допустимость сочетания «уклон / шаг стропил / снег» и число гвоздей в узле.
- **8.2.1.3** — ширина дома ≤9,8 м и шаг стропил ≤600 мм для применения таблиц.
- **6.2.4** — шаг балок ≤600 мм.
- **Табл. 5-1, 6-2, 6-3, 7-3, 8-6** — фундамент, чёрный пол, обрешётка, обшивки, кровельный настил.
- **6.2.10** — консоли: вылет ≤600 мм → сечение ≥38x235; >600 мм или нагрузка от этажей → ✗ расчёт.
- **6.2.11** — проёмы в перекрытии: сдваивание балок при длине >1,2 м и ширине >0,8 м;
  ✗ при длине >3,2 м или ширине >2,0 м.
- **8.2.1.8** — сечение накосных стропил (рядовое +50 мм по высоте, ширина ≥38 мм).
- **Табл. 12-1 и 12.2.1** — лестница: подступёнок 125–200 мм, проступь 235–355 мм, ширина ≥900 мм,
  ≤18 ступеней в марше, уклон ≤1:1,25; требуемая длина проёма считается из высоты в свету ≥1,95 м.

Проверки, которые выдаются как справка (геометрию не меняют): вентиляция крыши 8.7,
анкеровка 6.2.8.4, опирание перегородок 6.3, пожарные требования табл. 7-4, люк на чердак 8.8.

## Работа из Python напрямую

```python
import sys; sys.path.insert(0, "<$KARKAS>/scripts")   # каталог скилла
from karkas import build_house, report, bom, rules as R

res = build_house({"plan": {"length": 10.0, "width": 8.0}, "snow_kpa": 2.0})
print(report(res))
res.errors          # список нарушений
res.members         # список Member (kind, label, section, p1, p2, w_dir, group, note)
res.picked          # принятые сечения
res.levels          # ключевые отметки, м

# точечные расчёты без модели
R.pick_joist(4.2, 400)                      # -> '38x235'
R.rafter_max_span("38x184", 600, 1.5)       # -> 4.41
R.pick_lintel(1.8, "roof", snow_kpa=2.0)    # -> высота перемычки, мм
R.girder_max_span("4x235", 3.3, storeys=1)  # интерполяция по грузовой площади
R.check_stud("38x140", 600, 2.5, "external", "attic+1")
```

Внутри Blender:
```python
from karkas import build_house
from karkas import build as kb
res = build_house(spec)
kb.clear_scene(); built = kb.build(res)
kb.setup_scene(built["objects"], view="iso"); kb.render("out/view.png")
```

## Ограничения

### A. Требует данных за пределами СП 31-105-2002

Здесь норматив сам отсылает к расчёту — генератор не считает и говорит об этом явно.

| Что | Почему | Как ведёт себя модель |
|---|---|---|
| **Стропильные фермы** | 8.2.4.2: «Проектирование стропильных ферм… в соответствии с требованиями СНиП II-25». В СП только связи решётки ≥19x89 при сжатых элементах >1,8 м (8.2.4.3) | не генерируются |
| **Толщина утеплителя** | 9.2.1.2: определяется теплотехническим расчётом по ГСОП (СНиП II-3 / СП 23-101). Табл. 9-1 даёт только отношение Rрн/Rрв | слой строится по `layers.attic_insulation_mm`, выдаётся `!` с напоминанием о расчёте |
| **Пролёт накосных стропил** | 8.2.1.8 задаёт только сечение; таблиц пролётов для диагональных стропил в Приложении Б нет | геометрия строится, сечение по 8.2.1.8, выдаётся `!` с длиной накосного и требованием расчёта |
| **Сечение косоуров и тетив лестниц** | раздел 12 нормирует габариты и безопасность, но не несущую часть | строятся только ступени, выдаётся `!` |
| **Эркеры** | в тексте СП 31-105-2002 не упоминаются ни разу | не генерируются; ближайшее нормированное — консоли 6.2.10 |
| **Выход за 4.2.1 / 6.2.4 / 8.2.1.3** | табличные решения действуют только внутри этих границ | `✗` с указанием, какая граница нарушена |

### B. Нормы есть, геометрия пока не строится

| Что | Где нормы |
|---|---|
| Ендовы (возникают при Г-образном плане и слуховых окнах) | 8.2.1.8 — сечение как у накосных; 8.6.1 — фартуки и сливы |
| Слуховые окна | 8.2.1.10 — сдваивание стропил у проёма в кровле; 8.7.8 — защита от осадков |
| Непрямоугольный план (Г-, Т-образный) | нормативного препятствия нет — ограничение реализации |
| Вертикальные перекрёстные связи балок | 6.2.9.4 — строятся только горизонтальные (6.2.9.3) |
| Пол по грунту, подвал, дренаж | раздел 5 — проверяются размеры, геометрия не строится |

### C. Общее

**Это не замена расчёту.** Инструмент применяет табличные решения СП в границах их
применимости и честно сообщает, когда выходит за них. Узлы в расчётной схеме СП
рассматриваются как шарнирные (4.2.1).

## Переиспользование в другом проекте

Скилл самодостаточен: `references/` + `scripts/` не зависят ни от чего вне своего каталога.

```bash
# во всех проектах сразу (личный скилл)
cp -r <этот-каталог> ~/.claude/skills/karkas-blender

# только в конкретный проект
mkdir -p /путь/к/проекту/.claude/skills && cp -r <этот-каталог> /путь/к/проекту/.claude/skills/

# один источник правды вместо копий
ln -s <этот-каталог> ~/.claude/skills/karkas-blender
```

По желанию положи рядом со скиллом `sp31105-full.txt` и `SP-31-105-2002.pdf` — тогда будут
доступны точные формулировки и чертежи узлов. Проверка после переноса:
`python3 ~/.claude/skills/karkas-blender/scripts/selftest.py`

## Система координат

X — длина, Y — ширина, Z — вверх, метры. Z = 0 — верх фундамента (низ опорной доски).
(0, 0) — наружный угол каркаса. Габариты плана задаются по наружным граням каркаса.
В сечении `38x140` первое число — толщина вдоль стены/поперёк пролёта, второе — высота
(для стойки это толщина стены, для балки — высота на ребро).
