# karkas-sp31105

Параметрический генератор деревянного каркаса дома для **Blender** по
**СП 31-105-2002** «Проектирование и строительство энергоэффективных одноквартирных
жилых домов с деревянным каркасом».

Спецификация в JSON → каркас платформенного типа в Blender + **проверка соответствия нормам**
+ ведомость пиломатериалов. Таблицы СП (включая все 14 таблиц пролётов Приложения Б)
переведены в машиночитаемый вид, сечения подбираются автоматически.

Поставляется как [skill для Claude Code](#как-skill-для-claude-code), но работает
и как обычный Python-пакет.

---

## Требования

| | Нужно | Для чего |
|---|---|---|
| **Python 3.11+** | обязательно | проверка по нормам, подбор сечений, ведомость. Сторонних пакетов нет |
| **Blender 4.5 LTS+** | только для 3D | построение геометрии, `.blend`, рендеры. Используется штатный `bpy`, ставить ничего не нужно |

Всё, что не требует геометрии (режим `--check`), работает без Blender за секунды.

`blender` часто не прописан в PATH — подставляйте полный путь:

| ОС | Путь |
|---|---|
| macOS | `/Applications/Blender.app/Contents/MacOS/Blender` |
| Linux | `blender` или `/usr/bin/blender` (пакет `blender`) |
| Windows | `"C:\Program Files\Blender Foundation\Blender 4.5\blender.exe"` |

Проверка, что всё на месте:

```bash
python3 skills/karkas-blender/scripts/selftest.py
# OK — все проверки пройдены (248 элементов в эталонной модели)
```

Самопроверка сверяет ~35 контрольных значений прямо из таблиц СП и собирает эталонный
дом. Blender для неё не нужен — если она прошла, расчётная часть исправна.

## Быстрый старт

```bash
git clone https://github.com/eugene-chernyshenko/karkas-sp31105
cd karkas-sp31105
K=skills/karkas-blender

# проверка по нормам + ведомость, без Blender (секунды)
python3 $K/scripts/build_house.py --spec dom_9x7 --out out/dom --check

# геометрия, .blend и рендеры
blender -b --python $K/scripts/build_house.py -- \
    --spec dom_9x7 --out out/dom --render --views iso,front,side,top
```

Правки без файла спецификации:

```bash
python3 $K/scripts/build_house.py --check --out out/d \
    --set plan.length=10 --set plan.width=8 --set snow_kpa=2.0 \
    --set roof.slope=1:1.71 --set stud_spacing=400 --set storeys=2
```

На macOS вместо `blender` подставьте полный путь (см. [Требования](#требования)).

### Живая модель

Чтобы открытый Blender сам подхватывал каждую пересборку:

```bash
tools/install_autoreload.sh          # один раз
blender -b --python $K/scripts/build_house.py -- \
    --spec out/current.json --out out/current --open
```

Аддон `karkas_autoreload` следит за файлом и перечитывает его (несохранённые правки
в сцене не затирает — тогда просто пишет в `~/.cache/karkas/autoreload.log`).
`--open` запускает Blender, только если файл ещё не открыт.

## Что получается

| Файл | Содержание |
|---|---|
| `_report.txt` | проверка по СП (✓ / ! / ✗), принятые сечения, отметки, ведомость |
| `_bom.csv` | ведомость пиломатериалов: наименование, сечение, длина, шт, м³ |
| `_members.json` | все элементы каркаса с координатами — для своей постобработки |
| `.blend` | сцена с коллекциями по конструктивным группам |
| `_<ракурс>.png` | рендер: iso / front / side / top |

Каждый объект Blender несёт custom properties `kind`, `section`, `length_m` и `sp_note` —
ссылку на пункт СП, по которому элемент поставлен.

## Что строится

| Коллекция | Элементы | Пункты СП |
|---|---|---|
| `00_Фундамент` | схематичная лента | табл. 5-1, 5.4.7 |
| `01_Перекрытие_1` | опорная доска 38×88, обвязочные и крайние балки, балки, составной прогон, колонны, горизонтальные связи, чёрный пол | 6.2.1, 6.2.6, 6.2.8, 6.2.9 |
| `02_Стены_1` | нижняя обвязка, двойная верхняя обвязка, стойки, угловые стойки-нашивки, перемычки 2×(38×h) с прокладкой, опорные и крайние стойки проёмов, укороченные стойки, подоконные доски, связи жёсткости | 7.2.1–7.2.15, 7.2.5 |
| `03_Внутренние_стены` | несущие стены и перегородки | 7.2, 6.3 |
| `04_Лестница` | ступени прямого марша с проверкой габаритов | раздел 12 |
| `10_Крыша` | двускатная (стропила, затяжки, конёк, фронтоны, опорные стенки мансарды), вальмовая и шатровая (накосные, нарожники, центральные стропила вальм), плоская (кровельные балки) | 8.2–8.4 |
| слои | обшивки, утеплитель по ячейкам, пароизоляция, облицовка по обрешётке, подшивка потолка, кровельный настил — **по выключателям** | 7.3, 6.5, 9.2, 9.3, 10.3, 10.4 |

До 3 этажей. Крыши: двускатная, вальмовая, шатровая, плоская.
Проёмы в перекрытии (6.2.11), консоли (6.2.10), мансардные стенки (8.2.3.4), лестница.

### Слои оболочки

По умолчанию строится только каркас. Слои включаются по одному или сразу:

```bash
python3 $K/scripts/build_house.py --spec dom_valma_11x8 --out out/d --check \
    --set layers.wall_insulation=true --set layers.roof_deck=true
# или всё сразу:  --set layers=\"all\"
```

## Что проверяется

- **4.2.1** — этажность, высота этажа, шаг стоек, доля проёмов ≤ 30 % площади каждой
  несущей стены, снеговая нагрузка ≤ 3,0 кПа.
- **Табл. 7-1** — сечение / шаг / свободная высота стоек по виду стены и воспринимаемой
  нагрузке. Сечение крупнее табличного при том же шаге проходит (таблица задаёт минимум).
- **Табл. Б-1…Б-3** — пролёты балок перекрытий и чердачного перекрытия.
- **Табл. Б-4…Б-7** — кровельные балки и стропила по снеговой нагрузке.
- **Табл. Б-8…Б-11** — составные прогоны (с интерполяцией по грузовой площади) и коньковые балки.
- **Табл. Б-12…Б-14** — перемычки, с учётом жёсткой обшивки и нагрузки на стену.
- **Табл. 8-1** — допустимость сочетания «уклон / шаг стропил / снег» и число гвоздей в узле.
- **8.2.1.3** — ширина дома ≤ 9,8 м и шаг стропил ≤ 600 мм для применимости таблиц.
- **6.2.4** — шаг балок ≤ 600 мм.
- **Табл. 5-1, 6-2, 6-3, 7-3, 8-6** — фундамент, чёрный пол, обрешётка, обшивки, кровельный настил.
- **6.2.10 / 6.2.11** — консоли и проёмы в перекрытии: сдваивание балок и границы, за которыми нужен расчёт.
- **8.2.1.8** — сечение накосных стропил вальмовой крыши.
- **Табл. 12-1** — лестница: подступёнок, проступь, ширина, число ступеней, уклон, высота в свету.

Справочно (геометрию не меняет): вентиляция крыши 8.7, анкеровка 6.2.8.4, опирание
перегородок 6.3, пожарные требования табл. 7-4, люк на чердак 8.8.

Пример строки отчёта:

```
✓ [крыша/стропила] 38x184 @ 600 мм, пролёт 3.50 м ≤ 4.41 м (табл. Б-6, снег 1.5 кПа)
✗ [крыша/область применения] ширина дома по пролёту стропил 11.00 м > 9,8 м —
  таблицы Б-6/Б-7 неприменимы (8.2.1.3), требуется расчёт
```

## Расчёты без модели

```python
import sys; sys.path.insert(0, "skills/karkas-blender/scripts")
from karkas import rules as R, build_house, report

R.pick_joist(4.2, 400)                      # '38x235'
R.rafter_max_span("38x184", 600, 1.5)       # 4.41
R.pick_lintel(1.8, "roof", snow_kpa=2.0)    # высота перемычки, мм
R.girder_max_span("4x235", 3.3, storeys=1)  # интерполяция по грузовой площади
R.check_stud("38x140", 600, 2.5, "external", "attic+1")

res = build_house({"plan": {"length": 10.0, "width": 8.0}, "snow_kpa": 2.0})
print(report(res)); res.errors
```

## Ограничения

### Требует данных за пределами СП 31-105-2002

Здесь норматив сам отсылает к расчёту — генератор не считает и говорит об этом явно.

| Что | Почему | Поведение модели |
|---|---|---|
| Стропильные фермы | 8.2.4.2 отсылает к СНиП II-25; в СП только связи решётки ≥19×89 | не генерируются |
| Толщина утеплителя | 9.2.1.2: теплотехнический расчёт по ГСОП (СНиП II-3 / СП 23-101) | слой строится по заданному значению, выдаётся `!` |
| Пролёт накосных стропил | 8.2.1.8 даёт только сечение, таблиц пролётов в Приложении Б нет | геометрия строится, выдаётся `!` с длиной накосного |
| Сечение косоуров лестниц | раздел 12 нормирует габариты, не несущую часть | строятся только ступени, выдаётся `!` |
| Эркеры | в СП не упоминаются ни разу | не генерируются |
| Выход за 4.2.1 / 6.2.4 / 8.2.1.3 | таблицы действуют только внутри этих границ | `✗` с указанием нарушенной границы |

### Нормы есть, геометрия пока не строится

Ендовы (8.2.1.8), слуховые окна (8.2.1.10), непрямоугольный план, вертикальные
перекрёстные связи балок (6.2.9.4), пол по грунту и подвал (раздел 5 — размеры
проверяются, геометрия нет).

**Это не замена расчёту.** Инструмент применяет табличные решения СП в границах их
применимости и честно сообщает, когда выходит за них.

## Установка в Claude Code

### Как плагин (рекомендуется)

Репозиторий сам является marketplace — ставится в две команды:

```
/plugin marketplace add eugene-chernyshenko/karkas-sp31105
/plugin install karkas-sp31105@karkas-sp31105
```

Появятся skill `karkas-blender` и команды:

| Команда | Что делает |
|---|---|
| `/karkas-sp31105:build 9x7, 1 этаж, снег 1.5, двускатка 1:2` | собирает дом: проверка → геометрия → `.blend` и рендеры |
| `/karkas-sp31105:check балка 38x235 шаг 400 пролёт 4.5 м` | точечная проверка по таблицам, без Blender |

Skill подхватывается и без команд — достаточно попросить «построй каркас 10×8,
снег 2 кПа». Стоимость в контексте: ~230 токенов always-on, ~5,3k при срабатывании.

### Как личный skill, без плагина

```bash
cp -r skills/karkas-blender ~/.claude/skills/
# или один источник правды:
ln -s "$PWD/skills/karkas-blender" ~/.claude/skills/karkas-blender
```

Каталог скилла самодостаточен и работает из любого места. В клонированном репозитории
skill виден сразу — `.claude/skills/karkas-blender` ссылается на `skills/karkas-blender`.

Что стоит знать:

- **Windows:** `.claude/skills/karkas-blender` — git-симлинк. Без включённого developer mode
  или `git config --global core.symlinks true` он склонируется обычным файлом и skill
  в репозитории не подхватится. Ставьте плагином либо копируйте `skills/karkas-blender`
  вручную.
- Если поставить плагин **и** работать внутри этого репозитория, skill загрузится дважды —
  как `karkas-blender` и как `karkas-sp31105:karkas-blender`. Имена разные, конфликта нет,
  но ~230 лишних токенов в каждой сессии. В других проектах такого не будет.
